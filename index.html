PRIVACY AND POLICY

Приватність в ІТ визначається як право користувачів контролювати доступ, використання та розголошення своїх особистих даних. Це означає, що користувачі мають право знати, як їхні дані збираються, зберігаються та використовуються.

ОСНОВНІ ПРИНЦИПИ PRIVACY AND POLICY

  • Збір та зберігання даних
  • Доступ та контроль
  • Компанії повинні чітко комунікувати свою політику захисту особистих даних та умови використання
  • Дані користувачів повинні бути захищені від несанкціонованого доступу, зміни та видалення

ЯК ІМПЛЕМЕНТУВАТИ ПРИНЦИПИ?

  • GDPR — Загальний регламент про захист персональних даних
  • CCPA — Каліфорнійський закон про конфіденційність споживачів
  • Безпека даних — захист персональних даних від несанкціонованого доступу, витоку та крадіжки
  • Політики конфіденційності — узгоджені документи, що визначають, як збираються, зберігаються, використовуються та передаються персональні дані

GDPR — ЩО ЦЕ?

Загальний регламент про захист даних (Regulation (EU) 2016/679) — регламент в межах законодавства ЄС щодо захисту персональних даних усіх осіб у межах ЄС та ЄЕЗ.

Також стосується експорту персональних даних за межі ЄС. GDPR покликаний надати громадянам та резидентам ЄС контроль за їхніми персональними даними та спростити регуляторне середовище для міжнародного бізнесу шляхом уніфікації регулювання.

КЛЮЧОВІ РОЛІ В GDPR

Data Controller

Визначає цілі та способи обробки даних. Контролює, що збирається і для чого.

Data Processor

Обробляє дані від імені контролера. Дотримується інструкцій, забезпечує безпеку.

Data Subject

Людина, якої стосуються персональні дані. Має права згідно GDPR.

Data Protection

Принципи, процеси та технічні заходи для безпеки та цілісності даних.

СТАТТЯ 6 — ЗАКОННІ ПІДСТАВИ ДЛЯ ОБРОБКИ

Обробка персональних даних є законною лише за наявності однієї з підстав:

  • Згода — суб'єкт дав явну згоду на обробку
  • Контракт — обробка необхідна для виконання договору
  • Юридичне зобов'язання — вимога закону
  • Життєво важливі інтереси — захист життя особи
  • Публічне завдання — виконання завдань в суспільних інтересах
  • Законні інтереси — легітимні інтереси контролера (якщо не переважають права суб'єкта)

СТАТТЯ 6 — ПРИКЛАДИ ДЛЯ РОЗРОБНИКА

  • Згода — користувач натискає "Підписатись на розсилку", checkbox НЕ може бути pre-checked
  • Контракт — обробка email для створення акаунту, без акаунту сервіс не працює
  • Юридичне зобов'язання — зберігання фінансових транзакцій 7 років (вимога податкового законодавства)
  • Законні інтереси — fraud detection, аналітика безпеки, баланс між бізнесом і правами користувача

CCPA

California Consumer Privacy Act

CCPA — ЩО ЦЕ?

Каліфорнійський закон про конфіденційність споживачів (2020) — один з найсуворіших законів про захист даних у США.

Поширюється на бізнеси, що відповідають хоча б одному критерію:

  • Річний дохід > $25 млн
  • Обробка даних > 50 000 споживачів/пристроїв
  • Більше 50% доходу від продажу персональних даних

CCPA — ПРАВА СПОЖИВАЧІВ

  • Право знати, які дані збираються і як використовуються
  • Право на видалення персональних даних
  • Право відмовитись від продажу даних (Opt-Out)
  • Право на недискримінацію за використання своїх прав

Штрафи: $2,500 за ненавмисне / $7,500 за навмисне порушення (per violation)

ЯКА РОЛЬ ДЕВЕЛОПЕРА В ЛАНЦЮЖКУ GDPR?

Трудовий контракт

  • Без DPA, NDA та субконтрактів
  • Працюють від імені компанії
  • Компанія несе відповідальність

ФОП (підрядник)

  • Додатковий контракт + DPA
  • Може діяти як субконтракт від свого імені
  • Особиста відповідальність за дані

DPA — DATA PROCESSING AGREEMENT

Угода між контролером та оператором про обробку персональних даних

Є компанія, що займається роздрібною торгівлею та законно збирає інформацію про клієнтів. Вона — контролер.

Компанія залучає спеціаліста для email-розсилки, якому передає персональні дані. Він — оператор.

Саме ці відносини оформлюються у вигляді DPA.

https://legalitgroup.com/data-processing-agreement-uzgodzhennya-tamenedzhment/

DPA — КОЛИ ПОТРІБЕН РОЗРОБНИКУ?

  • Ви ФОП і працюєте з даними клієнтів замовника
  • Ваш сервіс зберігає/обробляє персональні дані від імені іншої компанії
  • Ви інтегруєте third-party сервіси (аналітика, CRM, email-провайдер)
  • Ви передаєте дані субпідрядникам

Без DPA — обробка даних є незаконною за GDPR

ТЕХНІЧНА ІМПЛЕМЕНТАЦІЯ

GDPR очима розробника

PRIVACY BY DESIGN / BY DEFAULT

Privacy by Design

Захист даних закладається на етапі проектування

Privacy by Default

За замовчуванням обробляються лише необхідні дані

  • Мінімізація обробки
  • Псевдонімізація даних
  • Обмеження періоду зберігання
  • Вдосконалення безпеки

АРХІТЕКТУРНІ ПАТТЕРНИ PRIVACY BY DESIGN

  • Data Minimization — збирай тільки ті поля, які реально потрібні для функціоналу
  • Encryption at Rest — шифрування даних у БД (AES-256)
  • Encryption in Transit — TLS/HTTPS для всіх з'єднань
  • Audit Trail — логування хто, коли і що робив з даними
  • Access Control — RBAC/ABAC для доступу до персональних даних
  • Data Retention — автоматичне видалення після закінчення терміну

COOKIE CONSENT

Перше, з чим стикається веброзробник

  • Банер має з'явитись до завантаження будь-яких трекерів
  • Необхідні cookies (сесія, CSRF) — без згоди
  • Аналітика (Google Analytics) — потрібна згода
  • Маркетинг (Facebook Pixel) — потрібна явна згода
  • Кнопка "Відхилити все" має бути такою ж помітною, як "Прийняти"

COOKIE CONSENT — ІМПЛЕМЕНТАЦІЯ

// Категорії cookies
const COOKIE_CATEGORIES = {
  necessary: true,   // завжди активні
  analytics: false,   // за замовчуванням OFF
  marketing: false    // за замовчуванням OFF
};

// Завантажити скрипти ТІЛЬКИ після згоди
if (consent.analytics) {
  loadScript('google-analytics.js');
}
if (consent.marketing) {
  loadScript('facebook-pixel.js');
}

Популярні рішення: CookieBot, OneTrust, cookie-consent (open source)

RIGHT TO BE FORGOTTEN

Стаття 17 — Право на видалення

Soft Delete

  • Поле deleted_at в таблиці
  • Дані залишаються в БД
  • Можна відновити
  • Не відповідає GDPR!

Hard Delete + Anonymize

  • Видалення PII з усіх таблиць
  • Анонімізація пов'язаних записів
  • Каскадне видалення з бекапів
  • GDPR-compliant

ERASURE — ПРИКЛАД API

// DELETE /api/users/:id/data
async function eraseUserData(userId) {
  // 1. Видалити персональні дані
  await db.users.update(userId, {
    email: 'deleted@anonymous.com',
    name: 'Anonymous User',
    phone: null, address: null
  });
  // 2. Видалити з third-party сервісів
  await analytics.deleteUser(userId);
  await emailService.removeSubscriber(userId);
  // 3. Залогувати факт видалення (без PII)
  await auditLog.record('USER_DATA_ERASED', userId);
}

RIGHT TO DATA PORTABILITY

Стаття 20 — Право на перенесення даних

  • Користувач має право отримати свої дані у машиночитабельному форматі
  • Формати: JSON, CSV, XML

  "orders": [...],

DATA BREACH NOTIFICATION

72 години

Стаття 33 — контролер повинен повідомити наглядовий орган протягом 72 годин після виявлення порушення

  • Detect — моніторинг, alerting (SIEM, IDS)
  • Contain — ізоляція, блокування доступу
  • Assess — які дані скомпрометовані, скільки суб'єктів
  • Notify — наглядовий орган (72 год) + суб'єкти (без зволікань)
  • Document — зафіксувати всі деталі інциденту

МІЖНАРОДНА ПЕРЕДАЧА ДАНИХ

Актуально для кожного, хто працює з хмарними сервісами

  • Вибір регіону — AWS eu-west-1, GCP europe-west1, Azure West Europe
  • Adequacy Decision — список країн, визнаних ЄС "безпечними"
  • SCC (Standard Contractual Clauses) — для передачі в "небезпечні" країни
  • Data Residency — дані фізично зберігаються в ЄС

Schrems II (2020): EU-US Privacy Shield визнано недійсним. Використовуйте SCC або EU-US Data Privacy Framework (2023)

КЛАСИЧНІ ПРОБЛЕМИ

  • Підписки — Фінляндія, 50к — немає згоди (ст. 6)
  • Автоматичні боти — збір даних без правової підстави
  • Розіграші зі списком людей — публікація PII без згоди
  • Батьківська згода — діти до 16 років (ст. 8)
  • Відбитки пальців при вході в спортклуб — 20к, Литва — надмірний збір (ст. 5)
  • Дискримінуючі алгоритми — Італія, 2.6М — профайлинг (ст. 22)
  • Купівля послуг ≠ Згода на одержання — Норвегія — ст. 6(1)(a)

GOOGLE

Порушення: ст. 7 (умови згоди) + ст. 12 (прозорість). Cookie banner не дозволяв легко відхилити cookies.

AMAZON

Порушення: ст. 6(1)(a) — відсутність валідної згоди на обробку для рекламних цілей.

Один із найбільших штрафів в історії GDPR.
