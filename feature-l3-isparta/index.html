OEM (Original Equipment Manufacturer)

  • Tied to a specific device
  • Cannot be transferred to another computer
  • Cheapest option
  • Installed by the manufacturer

Example: Windows on a new Dell/HP/Lenovo laptop

OEM прив'язана до конкретного пристрою. Не можна перенести. Найдешевша. Приклад: Windows на новому ноутбуці.

OEM (Özgün Ekipman Üreticisi)

  • Belirli bir cihaza bağlı
  • Başka bir bilgisayara aktarılamaz
  • En ucuz seçenek
  • Üretici tarafından yüklenir

Örnek: Yeni Dell/HP/Lenovo dizüstü bilgisayarda Windows

OEM прив'язана до конкретного пристрою. Не можна перенести. Найдешевша. Приклад: Windows на новому ноутбуці.

FPP (Full Package Product)

  • Retail (boxed) version
  • Can be transferred to another PC
  • Full documentation and support
  • Most expensive option

Example: Microsoft Office from a store

FPP — повна роздрібна версія. Можна перенести на інший ПК. Найдорожча. Приклад: Microsoft Office з магазину.

FPP (Tam Ürün Paketi)

  • Perakende (kutulu) sürüm
  • Başka bir bilgisayara aktarılabilir
  • Tam belgeler ve destek
  • En pahalı seçenek

Örnek: Mağazadan Microsoft Office

FPP — повна роздрібна версія. Можна перенести на інший ПК. Найдорожча. Приклад: Microsoft Office з магазину.

LICENSE TYPES BY OPENNESS

  • Trade Secret — code completely closed
  • Proprietary — can use, cannot modify
  • Freeware/Shareware — free to use, but closed source
  • Permissive (MIT, BSD, Apache) — open, minimal restrictions
  • Copyleft (GPL) — open, derivatives must also be open
  • Public Domain (CC0) — no restrictions at all
Огляд усіх типів від Trade Secret до Public Domain. Ключова ідея: відкритість не дорівнює безкоштовності.

  • Freeware/Shareware — ücretsiz kullanım, kapalı kaynak

CLA — CONTRIBUTOR LICENSE AGREEMENT

Agreement to transfer rights to a project contribution

  • Signed before the first PR to a large open source project
  • Grants the project the right to use your code
  • Author retains authorship but transfers licensing rights
  • Protects the project from future legal claims

DCO (Developer Certificate of Origin) — simplified variant: a git commit sign-off instead of a separate document

CLA підписується перед першим PR. Автор зберігає авторство, але передає права на ліцензування. DCO — спрощений варіант через git commit.

CLA — KATKI LİSANS SÖZLEŞMESİ

Projeye yapılan katkı haklarının devri anlaşması

  • Büyük bir açık kaynak projesine ilk PR'dan önce imzalanır
  • Projeye kodunuzu kullanma hakkı verir
  • Yazar, sahipliğini korur ancak lisanslama haklarını devreder
  • Projeyi gelecekteki hukuki taleplerden korur

DCO (Geliştirici Menşei Sertifikası) — basitleştirilmiş versiyon: ayrı belge yerine git commit imzası

CLA підписується перед першим PR. Автор зберігає авторство, але передає права на ліцензування. DCO — спрощений варіант через git commit.

TWO TYPES OF OPEN SOURCE

Permissive

  • Minimal restrictions
  • Derivative code can be closed
  • Commercial use OK
  • MIT, BSD, Apache

Copyleft

  • "Viral" license
  • Derivatives must also be open
  • Prevents "closing" the code
  • GPL, LGPL, AGPL
Два протилежних підходи: Permissive (мінімум обмежень, код можна закрити) vs Copyleft (похідні теж мають бути відкриті).

GPL — "VIRALITY"

What does this mean in practice?

  • Trigger: distribution of a derivative product containing GPL code
  • If you embed/link/copy GPL code → product must be under GPL (or compatible)
  • You must provide source code + license texts / copyright notices
  • SaaS: GPL usually does not require releasing code to service users (that's AGPL)

If the product is derivative and you distribute it — incompatible with proprietary licensing

Тригер — дистрибуція. SaaS-сервіси не потрапляють під GPL (для них є AGPL). Несумісна з пропрієтарним ліцензуванням.

GPL — "VİRALLİK"

Bu pratikte ne anlama gelir?

LICENSE COMPATIBILITY

Can they be mixed?

  • MIT + Apache = OK
  • MIT + BSD = OK
  • MIT + GPL-3.0 = OK (result will be GPL-3.0)
  • Apache-2.0 + GPL-3.0 = OK
  • Apache-2.0 + GPL-2.0-only = incompatible!
  • GPL-2.0-only + GPL-3.0 = incompatible!
  • GPL-2.0-or-later + GPL-3.0 = OK
MIT + Apache = OK. Apache + GPL-2.0-only = несумісні! Важливо перевіряти перед поєднанням залежностей у проекті.
