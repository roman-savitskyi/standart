ТИПИ КОМЕРЦІЙНИХ ЛІЦЕНЗІЙ

  • OEM - Передвстановлене ПЗ
  • FPP - Повний пакет продукту
  • Volume Licensing - Корпоративне ліцензування
  • Subscription - Підписка

OEM (Original Equipment Manufacturer)

  • Прив'язана до конкретного пристрою
  • Не можна перенести на інший комп'ютер
  • Найдешевший варіант
  • Встановлюється виробником

Приклад: Windows на новому ноутбуці Dell/HP/Lenovo

FPP (Full Package Product)

  • Retail версія (коробкова)
  • Можна перенести на інший ПК
  • Повна документація та підтримка
  • Найдорожчий варіант

Приклад: Microsoft Office в магазині

VOLUME LICENSING

  • Для організацій (5+ ліцензій)
  • Знижки при великих обсягах
  • Централізоване управління
  • Гнучкі умови оплати

Програми: Microsoft Open License, Enterprise Agreement

SUBSCRIPTION (ПІДПИСКА)

  • Щомісячна/щорічна оплата
  • Завжди остання версія
  • Cloud-based сервіси
  • Припинення доступу при несплаті

Приклади: Microsoft 365, Adobe Creative Cloud, JetBrains

ВИДИ ЛІЦЕНЗІЙ ЗА ВІДКРИТІСТЮ

  • Комерційна таємниця - код повністю закритий
  • Proprietary - можна використовувати, не можна змінювати
  • Freeware/Shareware - безкоштовно, але закритий код
  • Permissive (MIT, BSD, Apache) - відкритий, мінімум обмежень
  • Copyleft (GPL) - відкритий, похідні теж відкриті
  • Public Domain (CC0) - без обмежень взагалі

FREEWARE vs SHAREWARE

Freeware

  • Повністю безкоштовне
  • Всі функції доступні
  • Код закритий

Shareware

  • Безкоштовний trial
  • Обмежений функціонал або час
  • Потрібно купити повну версію

FREEWARE/SHAREWARE

Приклади:

  • Freeware: Telegram, Discord, Skype, VLC
  • Shareware: WinRAR, Sublime Text, TeamViewer

WinRAR - класичний приклад: працює після trial, але просить купити

ЧОМУ КОМПАНІЇ РОБЛЯТЬ OPEN SOURCE?

  • Dual Licensing - заробіток на enterprise версії

ДВА ТИПИ OPEN SOURCE

Permissive

  • Мінімум обмежень
  • Можна закрити похідний код
  • Комерційне використання OK
  • MIT, BSD, Apache

Copyleft

  • "Вірусна" ліцензія
  • Похідні теж мають бути відкриті
  • Захист від "закриття"
  • GPL, LGPL, AGPL

MIT LICENSE

Найпопулярніша Open Source ліцензія

  • Робіть що хочете з кодом
  • Лише збережіть copyright notice
  • Автор не несе відповідальності

SPDX: MIT

  • Потрібно вказувати зміни

GPL - "ВІРУСНІСТЬ"

Що це означає на практиці?

  • Тригер: розповсюдження (distribution) похідного продукту з GPL-кодом
  • Якщо ви вбудували/злінкували/скопіювали GPL-код → продукт має бути під GPL (або сумісною)
  • Потрібно надати вихідний код + тексти ліцензій/повідомлення про авторські права
  • SaaS: GPL зазвичай не вимагає видавати код користувачам сервісу (це робить AGPL)

Якщо продукт є похідним і ви його розповсюджуєте — несумісно з пропрієтарним ліцензуванням

GPL - ПРОЕКТИ

  • Linux Kernel - GPL-2.0
  • WordPress - GPL-2.0
  • MySQL - GPL-2.0 (dual license)
  • Git - GPL-2.0
  • GCC - GPL-3.0
  • GIMP - GPL-3.0

GNU LGPL

Lesser GPL - "слабший" copyleft

  • Для бібліотек
  • Можна лінкувати з пропрієтарним кодом
  • Зміни в самій бібліотеці - відкриті
  • Ваш код може залишитись закритим

SPDX: LGPL-2.1, LGPL-3.0

LGPL - ПРОЕКТИ

  • Qt - GUI фреймворк (dual license)
  • GTK - GUI бібліотека
  • FFmpeg - мультимедіа бібліотека
  • 7-Zip - архіватор

GNU AGPL

Copyleft для мережевих сервісів (SaaS)

  • Якщо ви змінюєте AGPL-код і даєте доступ до сервісу через мережу — користувачам треба надати вихідний код
  • Закриває "дірку" GPL, коли продукт не розповсюджують, а запускають як сервіс

SPDX: AGPL-3.0-only / AGPL-3.0-or-later

SOURCE-AVAILABLE ≠ OPEN SOURCE

Код видно, але права можуть бути обмежені

  • SSPL, Elastic License, BSL — приклади "source-available"
  • Часто забороняють певне комерційне використання (наприклад, як managed service)
  • Важливо: не всі такі ліцензії є OSI-approved

DUAL LICENSING

Подвійне ліцензування

  • Один продукт - дві ліцензії
  • Open Source (GPL) - безкоштовно
  • Commercial - платно, без обмежень GPL

DUAL LICENSING - ПРИКЛАДИ

  • MySQL - GPL або Commercial (Oracle)
  • Qt - LGPL/GPL або Commercial
  • MongoDB - SSPL або Commercial
  • Elasticsearch - SSPL/Elastic License

Бізнес-модель: Open Core

  • Використовуються в package.json, pom.xml
  • Машиночитабельні

СУМІСНІСТЬ ЛІЦЕНЗІЙ

Чи можна змішувати?

  • MIT + Apache = OK
  • MIT + BSD = OK
  • MIT + GPL-3.0 = OK (результат буде GPL-3.0)
  • Apache-2.0 + GPL-3.0 = OK
  • Apache-2.0 + GPL-2.0-only = несумісні!
  • GPL-2.0-only + GPL-3.0 = несумісні!
  • GPL-2.0-or-later + GPL-3.0 = OK

ПРАВИЛО СУМІСНОСТІ

Результуюча ліцензія = найбільш обмежувальна

Public Domain → Permissive → Copyleft

CC0 → MIT/BSD → Apache → LGPL → GPL → AGPL

Правило спрощене: важить, чи є це похідним твором і чи ви його розповсюджуєте

РЕАЛЬНІ СУДОВІ СПРАВИ

Чому ліцензії важливі

ORACLE vs GOOGLE (2010-2021)

  • Google використав Java API в Android
  • Oracle (власник Java) подав до суду
  • $9 мільярдів позов
  • 11 років судів
  • Верховний суд США: Fair Use (на користь Google)

Урок: API та їх ліцензування - складна тема

GPL VIOLATIONS

  • Cisco/Linksys (2008) - використали Linux в роутерах без відкриття коду
  • VMware (2015) - використали Linux kernel без GPL
  • Китайські виробники - масові порушення в IoT пристроях

Наслідки: судові позови, репутаційні втрати

ДЕ ДИВИТИСЬ ЛІЦЕНЗІЮ

  • LICENSE або LICENSE.md файл в репозиторії

  • README.md - секція License
  • GitHub - показує ліцензію автоматично

АРТЕФАКТИ ДЛЯ COMPLIANCE

  • LICENSE — текст обраної ліцензії
  • NOTICE / THIRD_PARTY_NOTICES — атрибуції та ліцензії залежностей
  • SPDX заголовки в файлах коду: SPDX-License-Identifier
  • SBOM (SPDX/CycloneDX) — інвентаризація компонентів

OpenChain (ISO/IEC 5230) — стандарт процесу OSS-compliance
